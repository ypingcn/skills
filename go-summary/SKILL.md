# go-summary

把长文本变成**能拿去做决定**的分析，而不是又一份更短的原文。

## 核心原则

1. **先分析，后问意图** —— 固定两步，不可颠倒：先按思维内核完成分析，再询问用户拿这段内容想做什么。
2. **事实是锚，分析是刀** —— 分析前先客观复述原文主张与关键数据，防止分析漂移、防止篡改原文观点。
3. **不分析无米之炊** —— 原文信息量不足时明说，不用空话硬凑四段式。
4. **全中文作答** —— 保留英文专有名词并搭配中文释义，不切换语种、不中英混杂。
5. **结论必须可落地** —— 战术部分给可执行动作，不给"加强沟通"式废话。

## 触发与不触发

### 触发（大段文本）

满足以下任一条件即判定为长文本：

- 纯文字字数 ≥ 100 字；
- 分段多、内容结构复杂（文案、故事、聊天记录、合同片段、随笔、试题、演讲稿等）；
- 含多行列表、对话、摘抄、截图转文字等复合型长内容。

输入来源：
- **对话中粘贴的长文** —— 直接使用。
- **网页链接** —— 用 `webfetch` 抓取正文后分析。

### 不触发

- 短句、词语、单问题、指令、短提问。
- 纯代码、纯日志、纯配置等以代码操作为主的输入。
- 用户已明确指定具体任务且文本很短（如"把这段里的错别字改掉"）。

**不触发时不要套四段式，也不要追问意图**——按用户实际要求直接干活。

## 执行流程

### 阶段 1：取内容

1. 粘贴的长文：直接进入阶段 2。
2. 网页链接：
   - 用 `webfetch` 抓取，优先取正文，去掉导航、广告、评论等噪音。
   - 抓取失败、需要登录、被反爬拦截时：说明失败原因，请用户直接粘贴正文，不要凭标题脑补内容。
   - 抓到的正文若不足 100 字且结构简单：按短文本处理，但若用户明确要求总结，仍给总结并说明原文信息有限。

### 阶段 2：事实提取

按 `PROMPT.md` 第 0 步在内部完成事实清单（核心主张 / 关键数据 / 涉及角色 / 隐含前提 / 可疑之处）。这一步不直接输出，但决定了分析是否会跑偏。

### 阶段 3：生成分析

按 `PROMPT.md` 的第 1-5 步产出正文，人格与文风依据 `references/os.md`。

输出结构（顺序固定，段首加粗标记）：

```
【原文要点】核心主张 + 支撑它的关键数据；≤3 句、≤200 字，不评论

【破局】刺破表象，直指背后的利益分配或结构性矛盾

【辩证】正反力量对比，量变与质变的关键节点

【战略与战术】宏观判断（加粗点题）+ 微观可执行动作（每条挂住"谁 / 何时 / 交什么"）

【实践反馈】当前策略的局限 + 需观察的核心指标 + 转向条件
```

### 阶段 4：询问意图 + 询问落盘（一次问完）

分析输出后，紧接着问两件事，**不要拆成两轮追问**：

```
以上是本次分析。你拿这段内容是想做什么？（此处列 2-4 个选项，由你根据这份原文的类型与内容现场生成，必须具体到这份原文）

需要我把它落盘成 markdown 文件吗？默认写到 <当前目录>/summaries/<日期>-<主题>.md，包含原文与分析全文。
```

- **问句骨架固定，选项不固定。** 意图那问必须出现，但选项要针对**这份原文**现生成 2-4 个具体用途，不要套"做决策依据 / 写进报告 / 评估风险 / 改写成稿 / 只是想读懂"这类通用清单。
  - 原文是经营纪要 → 给"追责任人 / 写进复盘 / 评估这版方案的风险"。
  - 原文是合同条款 → 给"查风险条款 / 对比现有版本 / 提炼关键义务"。
  - 原文是行业评论 → 给"找可迁移的观点 / 评估对我们业务的影响 / 写成内部材料"。
- **落盘那问固定**：默认路径与文件内容结构不变，用户可以改路径。
- 用户说明意图后，把分析往那个方向补一层（例如要做决策依据，就补"建议的下一步动作清单"；要写进报告，就补可直接引用的金句）。
- 用户回复"不用落盘" → 就此结束，不追问。
- 用户回复"落盘" → 进入阶段 5。
- 用户直接说了意图和落盘要求（而非问句）→ 意图问题不必重复问，只确认落盘。

### 阶段 5：落盘（可选）

1. 目录：默认 `<当前工作目录>/summaries/`，目录不存在则创建。用户指定路径时以用户为准。
2. 文件名：`<YYYY-MM-DD>-<主题>.md`，主题从原文标题或核心内容提炼，2-8 个字，不含空格与标点。
3. 内容结构：

```markdown
---
title: <主题>
date: <YYYY-MM-DD>
source: <来源 URL 或 "对话粘贴">
---

## 原文

<原文全文>

## 分析

<阶段 3 的完整输出>
```

4. 落盘后告知文件路径与文件大小即可，不要重复粘贴全文。

## 场景细分

| 场景 | 处理 |
|------|------|
| 长文本 + 用户附带提问/指令 | 依旧先完成分析，再询问意图，可顺带回答其附带问题 |
| 连续多条长文本 | 逐条分析（多于 3 条时先合并给整体判断），最后统一询问整体意图 |
| 原文是营销文案 / 自媒体文章 | 额外指出其说服结构与真实诉求，别被表面话术带走 |
| 原文是合同 / 条款 / 规章 | 重点拆"谁的权利、谁的成本、违约后果、争议解决"，硬事实优先于修辞 |
| 原文是会议纪要 / 聊天记录 | 还原"谁要什么、谁被拒绝、决策实际落点"，区分讨论与决议 |
| 原文信息量极低 | 直说信息不足并指出缺什么，不要硬凑四段式 |

## 错误处理

| 场景 | 处理方式 |
|------|---------|
| URL 抓取失败 / 需要登录 | 说明原因，请用户粘贴正文 |
| 原文超长（超过上下文承载） | 按段落分批读取，明确告知按哪几段处理，避免只覆盖开头 |
| 原文含大段代码或二进制噪声 | 剥离无关部分，只对可读文本做分析 |
| 原文含图片信息但无文字描述 | 说明无法读取图片内容，请用户补充要点 |
| 用户要求"不要分析，只翻译/润色" | 服从用户指令，退出四段式流程 |

## 文件说明

| 文件 | 说明 |
|------|------|
| `SKILL.md` | 技能定义：触发条件、执行流程、输出结构、落盘规范、错误处理 |
| `PROMPT.md` | 分析生成指令：事实提取 → 五段式生成 → 篇幅/文风/语言规范 → 禁止行为 |
| `references/os.md` | 思维内核与表达方式：唯物史观/矛盾分析/实践论、四步结构、总体基调、语言与格式规范 |
| `agents/openai.yaml` | 展示信息与默认提示 |
